Context Cloak

Privacy-preserving PII cloaking for MCP-assisted LLM workflows

Operating Mode

When enabled, Context Cloak assumes F5 AI Guardrails sits between the Inference VS and the LLM with PII detection active. All PII fields are forced to tokenize mode (substitution disabled) so cloaked values don't trip Guardrails PII patterns. The tokenize guidance prompt is always injected.

Wiring: This endpoint is for reference only. The Inference VS forwards to Guardrails by pointing its pool member at the Guardrails service; Guardrails then forwards cleared requests to vLLM. Configure pool members on the LLM Endpoint card accordingly.
Deployment Status: Not Deployed

Define which JSON fields in MCP responses contain PII and how to cloak them.

Guardrails Mode active: per-field mode is locked to Tokenize. Substitution is disabled because realistic fakes (e.g. fake SSNs, fake account numbers) would be blocked by Guardrails PII detection. Tokens (<<TYPE:ID:SEQ>>) pass through Guardrails cleanly and are reversed by the Inference VS.
